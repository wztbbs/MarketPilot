# 异常处理约定

platform 按处理责任划分异常边界。普通步骤默认上抛；拥有响应、执行状态、重试或降级决策的边界才捕获异常。方法拆分不意味着每个小方法都增加 try/catch，也不要求在 Controller 捕获所有执行异常。

## 处理边界

| 边界 | 负责的决定 | 日志归属 |
| --- | --- | --- |
| 应用问答入口 | 完成本轮失败记录、Trace 和用户响应 | 应用入口记录异常链与 traceId；平台中间层不重复打印 |
| AgentDispatcher.executeBudgeted | 为上下文组装、Agent 执行、交付失败补齐 Router 用量和结果计数 | 保留原因与 suppressed，继续上抛给应用入口 |
| ReAct／Plan 执行边界 | 模型修复、预算降级、保留失败时的用量与证据 | 预期修复记录 Trace；未处理异常带上下文上抛 |
| DAG 节点边界 | 隔离单节点工具失败，使独立节点仍可执行 | 转成节点失败的异常在此记录 traceId、nodeId 和异常链 |
| RunCoordinator.drive | 完成运行、等待调用或记录运行失败 | 转成运行失败的异常在此记录 runId、traceId 和异常链 |
| RunCoordinator.publish | 重试业务结果提交 | 在此记录 runId、traceId 和异常链，不改写已经确定的执行结果 |
| ToolGateway.process | 提交前拒绝、工作池重试、确定失败或外部结果不确定 | 预期拒绝记 INFO，工作池满记 DEBUG，系统故障记完整异常链与 runId／invocationId |
| RunReconciler | 收口扫描线程和独立工作线程的故障，允许后续扫描继续补偿 | 扫描故障记 ERROR；任务故障记 kind、id 和异常链 |
| HTTP／LLM 适配器 | 将协议错误转成受控结果或有 cause 的技术异常 | 继续上抛的不重复打印错误日志；调用 Trace 仍在调用位置记录 |
| 可选证据存储 | 明确的存储不可用允许 PARTIAL | 在唯一降级边界记录 traceId、Agent、工具、位置和异常链 |

异步工作线程是独立入口，扫描线程无法捕获它的执行异常。扫描与工作线程因此各自收口，不能依赖一次外层 try/catch。

## 异常语义

- `ModelOutputException`：只表示模型 JSON、决策、证据引用或模型参数校验失败。仅这类异常进入 ReAct 的模型修复或回答非法降级。普通 `IllegalArgumentException` 可能来自客户端、工具或回调，必须继续传播。
- `RunSuspended`：携带 RunWaitTarget 的等待控制信号，工具结果与方案审批分别关联持久化对象，交给 RunCoordinator 保存 WAITING，不作为错误记录。
- `RunLeaseLostException`：旧执行者已失去所有权，立即停止。不能转成节点失败、模型修复或可选证据存储降级。RunCoordinator 不再以旧执行者身份改写结果。
- `ExecutionFailure`：携带用量、证据及业务私有结果。补充 Router 用量时保留原始 cause 和收尾失败的 suppressed 异常，不重复计费或丢失已经发生的调用。
- `ToolEvidenceCheckpoint.PersistenceUnavailable`：明确的可选证据存储不可用。数据库存储故障在 writer 调用处转换；运行日志、租约与检查点写入不属于可选存储，失败必须上抛。
- 其他运行时异常：由最近的执行边界作出失败／重试决定，或继续上抛给应用入口；禁止泛化成“模型输出错误”。

普通工具的业务失败可以通过 `ToolResult` 表达。HTTP 工具的已知网络、信封、证据格式错误继续返回既有状态码；响应校验捕获只包围响应校验。请求构造或客户端程序错误不再一律返回 OUTPUT_INVALID。

外部调用前发生的系统异常保存 FAILED／EXECUTION_ERROR；进入外部调用阶段后的异常可能意味着外部已经受理，保存 UNKNOWN 并安排查单。工作池拒绝接收请求时没有发起外部调用，恢复原状态并延后重试。

## 日志与原因保留

负责吞掉异常、转换成状态或作出降级决定的边界负责记录。继续上抛的中间层通常只转换协议或补充上下文，保留 cause，不再次打印 ERROR。正常等待和重复键竞争不需要异常堆栈；预期的模型校验失败通过 Trace 保留反馈。

失败路径中的 Trace 写入故障不能覆盖原始执行异常。`TraceSink.recordFailure` 将记录故障附加到原异常的 suppressed，由最终处理边界一起记录。业务交接收尾故障同样保留为 suppressed。

HTTP 工具沿用既有脱敏契约：`http_tool_attempt` 只记录工具、服务标识、尝试次数、HTTP 状态与受控错误码，不记录 URL、凭证或依赖错误正文。服务地址配置的校验错误也采用脱敏信息；这一处有意不附加可能包含地址或凭证的原始 URI 异常。

## 事务与恢复

同一业务原子操作中的多行数据库修改，使用短事务；网络、模型调用和等待过程不置于长事务内。事务不能判断外部动作是否成功，也不能撤销已经提交到外部服务的操作。

本次整理保留已有业务提交事务、租约、revision／fencing token、冻结参数、稳定调用 ID、幂等和推拉补偿。调用结果保存与唤醒之间即使发生进程退出，仍由到期扫描补偿，无需为了减少 catch 把网络执行包进事务。没有新增表结构，也没有重新执行 MySQL 强杀测试；此前故障验证记录保持原样。

## 捕获位置检查范围

| 范围 | 整理结果 |
| --- | --- |
| AgentDispatcher、IntentRouter | 编排失败集中补齐计数；路由修复只捕获模型输出异常；交接故障保留 suppressed |
| ReactEngine、PlanEngine、DeclarativePlanHooks | 收窄模型修复／回答降级范围；控制信号继续传播；保留失败时已累计的计数 |
| DagExecutor | 保留节点隔离；控制信号、任务级故障、中断继续传播；Future 保留原因；日志带节点与 Trace |
| ToolGateway、RunCoordinator、RunReconciler | 按执行边界分类处理，补齐终结、重试及后台任务日志 |
| ToolEvidenceCheckpoint | 集中可选存储降级，检查点和程序错误继续传播 |
| HttpAgentTool、OpenAiCompatibleClient、LlmCallService | 收窄协议转换范围，移除继续上抛路径的重复错误日志，避免 Trace 故障覆盖原异常 |
| LlmJson、PlanningJson、PromptStore、ToolDefinitionLoader | 仅捕获实际解析、I/O 或配置异常；保留原因并交给使用方处理 |
| AgentDefinitionLoader、DurableStore | 保留配置加载与 JSON 存储边界的必要转换，不重复记录日志 |
| QueryBudget、RunScope、HarnessRolloutConfig | 保留 Future／中断与摘要算法的必要转换；失去运行所有权使用专用异常 |
| ClarificationField、ToolOutputSchema、PlanValidator、CalculationTool | 保留纯格式校验、数值解析及计算失败转换；不吞执行与存储异常 |
| HttpToolServices | 保留服务配置校验的脱敏边界，捕获范围收窄为参数异常 |

## 本地验证

新增测试覆盖工具／回调异常不触发模型修复、回答客户端故障不伪装为非法回答、失败时完整用量保留、交接 suppressed 保留、租约丢失跨 DAG 传播、证据存储降级日志、检查点故障继续传播、Trace 故障不覆盖主异常，以及后台故障后继续扫描。HTTP／LLM 适配器测试只访问 localhost 模拟服务。
