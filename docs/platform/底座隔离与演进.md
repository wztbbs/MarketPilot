# 底座包结构、依赖与扩展端口

核对日期：2026-11-12。当前已建立 package 与公共契约边界，提供工具控制和持久化运行，并已适配 Query／Monitor。仍使用一个 Maven 工程和一个 Spring Boot 主应用；底座独立打包／发布尚未建设。

本页负责包和依赖；执行职责见[底座架构](底座架构.md)，工具与恢复协议见[工具控制与可恢复运行](工具控制与可恢复运行.md)。CEX 的接入细节及验证范围见[业务运行适配](../cex/Monitor与Query运行迁移.md)。

## 包结构与依赖

```text
com.cexpilot
├── Application                         主应用启动入口保持原名
├── platform
│   ├── agent                           公共 Agent、输入输出、注册、路由、分发
│   ├── context                         上下文、路由方言、交接扩展端口
│   ├── engine
│   │   ├── react                       ReactEngine
│   │   ├── plan                        PlanEngine、PlanHooks、自驱动接入契约
│   │   └── dag                         通用节点、依赖、校验、分层调度及节点执行端口
│   ├── tool                            工具契约、注册、参数与 HTTP 适配
│   │   ├── control                     工具控制、授权与目标版本检查扩展
│   │   └── calculation                 通用确定性算子
│   ├── run                             持久化运行、调用记录、检查点与推拉调度
│   ├── execution                       结果、异常、时间与预算上下文
│   ├── evidence                        会话引用和工具证据保存端口
│   ├── llm                             客户端、调用审计、用量与模型配置
│   ├── prompt                          模板加载和渲染
│   └── observability                   Trace 契约、节点事件和 HTTP 计数
├── business.cex
│   ├── query                           Query Agent、专用 Planner/Runtime、继承与事实绑定
│   ├── monitor                         Monitor Agent、草稿、确认、调度、执行和投递
│   ├── context                         CEX 上下文、路由方言、Agent 名称保留策略
│   ├── handoff                         Query → Monitor 条件交接
│   ├── conversation                    会话、查询 Task/TaskVersion 与持久化
│   ├── metric                          指标目录、编译、Provider 与指标节点执行扩展
│   ├── market                          交易所客户端和行情服务
│   ├── evidence                        行情事实、缓存与工具证据保存实现
│   ├── api                             现有 API/SSE/应用服务
│   └── ...                             既有时间、Trace 存储、评测、ETH、MCP 等业务模块
└── bootstrap.configuration              LLM 客户端与时间基础设施装配
```

依赖方向：business.cex → platform；bootstrap → platform/business.cex。platform 不得引用 business、bootstrap 或以前的根级业务包；business 不得反向依赖 bootstrap。应用的 Bean 实现底座端口，Spring 按类型注入，底座不通过业务类名做反射装配。

配置仍使用原有属性前缀、Bean 名与资源路径。`QueryBudget`、`QueryExecutionConfig` 及历史统计字段暂保留名称与口径，以保持现有配置、Trace 和 API 行为；这些公共类型已不依赖查询业务类型。通用持久化运行通过 platform.run 另行建模，不与查询 TaskVersion 或监控规则混用。

## 输入输出边界

公共 `AgentExecutionRequest` 接收 `AgentInput`；Query 的 PlanningContext 与旧入口回调通过 CexAgentInput 留在业务侧，不进入底座类型。

CEX 入口通过 `CexAgentInput` 提供这些数据。`AgentContextAssembler` 实现 `AgentContextProvider`，生成原有模型上下文，并且仅为 MarketAnalysisAgent 构造 QueryInput；Monitor 和声明式 Agent 不接收查询私有对象。

公共 `ExecutionResult` 和 `ExecutionFailure` 使用 `AgentOutput` 携带类型化业务结果，不再引用 TaskScope。Query 通过 `QueryOutput` 保存 TaskScope 与最终 CompiledPlan，AskService 在业务包中取出并提交查询任务版本；恢复结果由 ConversationRunCommitter 提交。QueryRunAdapter 的输入快照不包含回调，最终计划从 QueryOutput 恢复。Router 用量合并、异常包装和结果复制会保留该私有结果。

`BasicAgentContextProvider` 提供无业务依赖的默认上下文投影；其他业务不必构造 CEXPilot 对象。没有交接扩展时使用 `DispatchLifecycle.none()`。

## 扩展端口

| 底座端口 | CEXPilot 实现 | 边界 |
| --- | --- | --- |
| AgentContextProvider | AgentContextAssembler | 底座不解析 query_task、monitor_context 内部结构 |
| RoutingDialect | CexRoutingDialect | Query 改写范围和业务兜底文案由应用提供；候选来自注册表 |
| DispatchLifecycle | AnalysisMonitorHandoff | 保留原条件投影、交接与失败事件，不把业务交接写进 Dispatcher |
| AgentRegistrationPolicy | CexAgentRegistrationPolicy | Query/Monitor 名称保留属于应用；底座只保留公共 clarify 路由约束 |
| ToolEvidenceWriter | EvidenceStore | 公共引擎只保存通用工具证据并取得稳定 ID，不依赖行情事实类型 |
| NodeOperation | MetricQuery | 通用节点持有类型化扩展请求，不直接包含 MetricQuery 字段 |
| NodeExecutionSupport | MetricNodeExecutionSupport | Provider、历史绑定、指标计算元数据及 METRIC_RESULT/FACT_REUSED 事件留在业务包 |
| NodeBindings | ExecutionBindings | 由相应业务节点执行器解释可信绑定 |

通用 DAG 仍负责拓扑分层、并发、超时、依赖失败和结果收集。CEX 扩展保留原指标 Provider 调用、历史 payload 复用、单位/质量校验、计算来源传播和 Trace 事件。声明式 Plan 的普通工具节点不需要该扩展。

## 现有 Agent 路径

```text
Query:
AgentDispatcher → RunCoordinator → QueryRunAdapter → PlanEngine → QueryPlanHooks.planSelfDriven → DagRuntime / DagPlanner

Monitor:
AgentDispatcher → RunCoordinator → MonitorRunAdapter → PlanEngine.drive → MonitorPlanHooks → ToolGateway → 监控草稿服务

声明式 Agent:
AgentDispatcher → ReactEngine 或 PlanEngine / DeclarativePlanHooks
```

Query 的自驱动路径保留，没有把专用规划状态机迁入通用循环，也没有删除 planSelfDriven。Monitor 继续管理草稿、确认、启用、后台执行和投递；现有监控恢复机制仍是业务内部能力，通用声明式运行另行建模。

工具执行已接入 ToolGateway；HTTP 操作必须显式声明控制语义，原只读工具及 Agent 工具白名单继续生效。声明式和两个业务 Agent 的对话运行均经 RunCoordinator 管理等待与恢复，Query 自驱动状态机没有改造为通用循环。详细检查点、工具权限和后台监控边界见[Monitor 与 Query 运行迁移](../cex/Monitor与Query运行迁移.md)。

## 装配与部署

主入口仍为 `com.cexpilot.Application`，扫描新的平台、业务和装配包。没有修改 start-class 的打包约定。通用运行使用 platform_run、platform_tool_call、platform_run_checkpoint 和 /api/agent-runs 接口；现有 API 路径保留。

独立行情 MCP 入口随业务包迁移为：

```bash
mvn spring-boot:run -Dspring-boot.run.main-class=com.cexpilot.business.cex.mcp.server.FundingMcpServerApplication
```

其独立 profile、仅装配客户端层及交易所代理要求保持不变。生产构建应使用 clean，避免旧 package 的 class 文件留在包中导致重复组件。

## 验证

先运行 `mvn clean test-compile`，再选择直接相关测试。不要因移包而默认执行线上回归、收费模型重放或全量单测。

- PlatformBoundaryTest：检查源码引用与编译后常量池，阻止底座反向依赖业务/装配及旧根级包，并阻止业务依赖装配。
- PlatformAgentIsolationTest：一个仅引用 platform 的笔记数量 Agent，分别通过 React、Plan 跑通真实注册、路由、本地 HTTP 工具与答案交付；使用假模型，不访问外部服务。
- MonitorApplicationContextTest：完整应用以 H2 启动，验证 Spring 装配、两个内置 Agent、配置绑定与现有 API。
- Query/Monitor、DAG、工具、会话、交接和错误计量的直接测试：验证原行为和私有结果在公共包装中没有丢失。

这些验证证明当前 package 边界与接入路径成立，不表示底座已经可以独立发布，工具控制与恢复的验证和适用边界见[工具控制与可恢复运行](工具控制与可恢复运行.md)。
